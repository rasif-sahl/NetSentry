# Phase 9 verification and device handoff

Date: 16 November 2026. Implemented directly on develop, with feature/platform commits pushed to origin/develop. Flutter mobile/ and native ios/ remain unchanged. No Android Studio, mobile SDK, emulator, simulator, Xcode or Gradle distribution was installed or invoked. Existing temporary standalone Kotlin/JDK tooling and checksum-pinned JVM JSON/HTTP libraries are used for portable checks only.

## Delivered source

- Public Android usage-event adapter and checkpointed reducer for foreground/screen intervals, observed foreground entries, first/last use and incomplete/unsupported context. Screen APIs are gated from API 28 and activity instance identity from API 29; older cases stay explained/unavailable.
- Separate app-usage-v1 consent, encrypted two-source queue with byte/count/retry bounds, four-batch drain, generation/context clearing and persistent offline permission-health acknowledgement.
- Detailed authenticated batch endpoint, atomic measurement/history/daily aggregate/replay storage, eleventh explicit migration, app metadata/unknown classification, owner corrections/custom categories, scoped reports/comparisons/trends/CSV and deterministic evidence-based insights.
- Compose Apps screen, locally permitted icons, app/category/device filtering, counts/timelines/quality, screen/app limit progress and permission/offline/missing-report alert controls. Native compilation/rendering is pending.
- Missing-report alert semantics based on accepted usage receipts, with intentional-pause suppression; web creation/editing support. OpenAPI 1.9.0 documents 92 operations.

## Available checks

- Standalone Kotlin compiles the actual portable Policy, reducer, Wire, HTTP and Repository source. The suite covers queue/consent/refresh/authorization boundaries, two-source delivery, immutable lost-response retries, byte capacity, generation/scope clearing and pending health work. Reducer fixtures cover unknown boundaries, activity handoff, duplicate events, multi-window unions, open-session clipping, lock/restart, unsupported APIs and bounded truncation. All 45 JVM cases (31 repository/policy and fourteen reducer checks) pass; final hosted outcome is recorded in the task handoff.
- Kotlin PSI parses all fourteen application source files. This is syntax checking, **not** Android/Compose type resolution, lint, APK creation or runtime verification. AJV validates actual Kotlin-emitted synthetic application and measurement/capability/command payloads against shared schemas. Fifteen contract regressions pass.
- Actual Kotlin OkHttp adapters run over temporary trusted loopback HTTPS to real NestJS/PostgreSQL: profile/notification PATCH, separate enrolment/consent, network plus detailed app upload/report, categories/corrections, filtered CSV, usage/health rules, remote request/cancel and erasure/sign-out. Redirect refusal and exactly one mutating POST after synthetic HTTP 503 are asserted. OS events and desktop observations are explicit fixtures, not phone telemetry or a native shutdown.
- Real API/PostgreSQL checks exercise addendum denial with atomic rollback, concurrent replay, changed metadata conflict, overlap/duplicate rejection, screen union versus concurrent app sums, first/last/counts, midnight alignment with threshold aggregates, category corrections/reset and own/shared report isolation. Missing uploads alert despite fresh heartbeats; intentional pause resolves the condition.
- Actual maintenance checks use a simulated future job date to verify raw-window expiry, surviving daily summaries and receipt replay without resurrecting deleted detail. A direct persistence fixture separately checks New York's 25-hour DST day and late-night overlap clipped at local midnight; it does not bypass production ingestion or assert physical-device results. Fresh-password privacy service export covers the new owned fields; existing HTTP privacy checks retain their real rate limits and pass separately. Erasure clears catalogs/windows/days.
- Clean migration, constraints/cascades, rollback, schema-drift refusal and baseline adoption pass with eleven migrations. Root checks include backend compilation and 41 tests across twelve suites, desktop type/production build, web lint/production build and shared contracts. Browser/hosted final results are recorded in the task handoff.
