# Desktop diagnostics and safe crash recovery

Source implementation targets the packaged macOS desktop. Existing agent/socket tests also run on supported Unix development hosts. No mobile SDKs, Xcode, simulators or emulators were installed; Flutter remains untouched. No production service or real monitoring workload was used for recovery testing.

## Operation

Open **Diagnostics and recovery**, then choose **Check desktop diagnostics**. Checks run only on request. They inspect service ownership/partial receipts and validate supported application placement/signatures before invoking the fixed bundled helper. The helper checks private state, the runtime lock, socket state, configuration, local background choice and current pairing/workspace eligibility. Credential access may prompt Keychain; the last check may make one authenticated configuration GET to the paired backend. No collectors, uploads, consent changes or pairing reconciliation run. If another agent/helper holds the lock, remaining helper checks are skipped and the UI says so. These are current checks, not historical crash logs or proof of accurate monitoring.

Failures use a fixed public code/message vocabulary: unsupported platform, app placement, signing, missing/unsafe state, unavailable/busy lock, absent/live/stale/unsafe/changed/unknown socket, configuration, unavailable credentials, missing/rejected/stale pairing, local background choice, backend availability/rejection and workspace grant. Raw OS/HTTP errors, credentials, paths and identifiers never become report messages. Service actions also expose fixed actionable failures and preserve ownership evidence when incomplete. Partial receipt-only registration is identified explicitly and must be removed before recovery.

For **Repair stale socket**, first remove the owned background service. The desktop requires a verified service-absent result and a trusted app, then native confirmation with Cancel selected. It rechecks these conditions after confirmation. The signed helper rechecks private configuration and acquires the same exclusive runtime lock used by agents and update helpers. The state directory must resolve canonically with no symlink components. The fixed `agent.sock` must be a current-user Unix socket with mode 0600. Only a refused connection counts as evidence of no listener; timeouts, permissions, missing/changed paths and other uncertainty block deletion. The helper compares file identity and mode again before unlinking. Cooperative agent startup is excluded by the runtime lock and the state directory is private; this is not a defense against malicious code already running as the same user and replacing private paths.

Recovery removes only the verified stale socket. It never signals a PID, executes a shell, deletes a lock/config/receipt/credential, clears queued data, changes permissions or consent, or starts/restarts an agent. A runtime lock file may be created by the standard lock acquisition if absent and is retained normally. After a successful repair, explicitly start the foreground agent or register the service again. Backend permission is diagnostic information, not a prerequisite for clearing a locally verified dead socket; valid private configuration and trust remain required. API/Keychain outages may make eligibility unknown without granting authority.

Use **Export redacted diagnostics** after reviewing results. Export refreshes checks and opens a native save dialog. The renderer cannot supply a path or report. The JSON contains a schema version, time, app version, OS/architecture, fixed result codes/messages/next steps and recovery eligibility. It omits installation/workspace/device IDs, addresses, project/process names, filesystem paths, tokens, raw logs and backend payloads. Saving creates a mode-0600 new file exclusively and refuses existing files/symlinks. Cancellation makes no export. Review the report before sharing; nothing is uploaded automatically.

## Verification

- Go race-enabled tests cover private dead socket detection/repair, live listeners, regular files/symlinks, socket/directory permissions, linked state, replaced socket identity, uncertain probe failures, retained runtime exclusion and idempotent absence.
- Desktop tests cover trust gating, native-confirmation cancellation, revalidation after service/trust/socket changes, partial records, blocked repair, strict helper result parsing and positive-allowlist export. File export tests verify private mode and refusal to overwrite regular files/symlinks.
- Actual temporary development-agent checks kill a controlled unpaired foreground agent, diagnose its stale socket, repair it, compare configuration and credential bytes, and explicitly restart it. Further checks refuse a live socket even without a cooperative agent lock, refuse unsafe paths and reject an active update lease. Synthetic backend checks verify grant denial/allowance, generation mismatch and rejected credentials/backend health using GET-only requests with consent unchanged.
- Chromium renderer checks verify initial disabled actions, explicit check/repair/export bridge calls, cancellation, and existing appearance/responsive/keyboard/control regressions. They do not exercise native dialogs, Keychain or actual service mutation.
- `TEST_AGENT_BINARY="$PWD/artifacts/netsentry-agent" npm run test:desktop-diagnostics` runs the focused checks after building the agent and desktop. The existing `test:desktop-updates` glob includes these tests in repository checks and CI.

Local verification passed: repository `npm run check`, Go race tests, all **30** desktop lifecycle/update/diagnostic tests, Chromium UI checks and actual authenticated IPC. The unsigned arm64 preview rebuilt, and packaged diagnostic/lifecycle modules and bundled agent matched the verified build byte for byte. Production policy remained disabled with no signing team.

Signed/notarized packaged Electron acceptance remains pending because no production Developer ID identity is configured. Verify actual native dialogs, Keychain denial/lock behavior, signed helper execution and a controlled crash/recovery/login sequence on a supported signed install. Unsigned previews can display trust/service diagnostics and export those results, but cannot invoke the packaged agent or repair a socket. Do not weaken trust to bypass this gate.
