# Phase 13 validation record

## Implemented source

Business workspaces now provide multiple organizations/account, locations and networks/location, departments, verified-member employee enrolment/restoration, employee/device assignment, separately declared company custody, explicit employee sharing and withdrawal, organization/location/department aggregate reports and exports, reporting compliance checks, network alert ownership/resolution, minimal audit views/exports, remote unenrolment and offboarding. Observed network endpoints can receive revision-bound department metadata independently of an employee; association never establishes ownership, connectivity or traffic attribution.

The role matrix separates organization owner, administrator, network administrator, analyst, viewer and employee. Existing service control still needs named computer-owner grants and local consent; Business roles do not create that authority. Billing is an owner-only authorization gate; subscription/payment operations remain Phase 14. Roles apply organization-wide; locations are reporting dimensions, not additional access grants.

The web dashboard implements organization administration and employee consent. Android and SwiftUI source add employee assignment/compliance views and explicit sharing/withdrawal against current device generation and assignment revision. Sharing does not turn on monitoring or grant OS permission. Android refresh skips unavailable service inventory for employee/network-admin roles and stops collection/clears an installation binding when workspace membership is lost. Both clients clear Business data on scope loss/logout. Flutter remains unchanged.

## Rollout and remaining gates

Apply migrations fourteen and fifteen explicitly before using Business routes. Schedule bounded `business:work <organizationUUID>` cleanup alongside existing monitoring, family, network and agent workers. Business audit keeps 90 days; the audit projection retains network/developer sources only for their existing 30/7-day windows. Down migrations remove Business metadata/links; monitored usage remains under its existing ownership/retention policy. No production scheduler is created here.

Native app/extension/Compose/SwiftUI type checking and packaging/signing remain pending. Physical acceptance must verify employee/BYOD consent, OS permissions and unsupported fields, actual monitoring accuracy, offline revocation and local purge delivery, mobile UI/accessibility, corporate device handoff/re-enrolment and remote unenrolment. Server credential rejection is immediate; an offline device can only learn about it on reconnection. Actual router/firmware support, security posture enforcement, Apple provisioning and push delivery remain unverified/unconfigured. Reporting checks are observations, not a security, legal-compliance or employee-productivity certification.
