# Account export and deletion

An authenticated user can export their currently implemented personal profile/preferences, own device records, own device consent/permission history, current workspace memberships, login-session metadata and privacy-event history. Export requires their current password, uses a repeatable-read transaction, and masks other actors' identifiers in device events. It excludes password/refresh/device hashes, action tokens, encrypted mail payloads and other members' private records. API responses use Cache-Control: no-store.

Account deletion requires the current password and explicit DELETE confirmation. It locks referenced workspaces in a stable order before the account and rechecks references to prevent concurrent membership/ownership changes from bypassing safeguards. Owners must transfer a shared workspace while it has other members or other people's device records. Personal/otherwise solely-owned workspaces are removed, then the account is deleted transactionally.

Foreign keys remove sessions, account actions, queued mail, enrolments, owned devices/history and privacy records. Actor references in other people's retained device events are set to null. Transferred workspaces and other users' records remain. Deleted user/device credentials stop authenticating, including old refresh tokens and opaque installation tokens. The API returns a deletion receipt; it does not claim to erase email already delivered or every historical backup immediately.

Device-specific erasure can be requested by its owner even after leaving a workspace. It clears currently stored collection metadata and history, disables collection, revokes the installation credential to prevent metadata reappearing without fresh enrolment, advances the generation and leaves a minimal deletion event/identity tombstone. Later measurement stores, export files and offline agents must attach their own retention/deletion handlers to these boundaries before collecting data; they do not exist in Phase 2. Backup retention and device-side erasure acceptance remain deployment/native responsibilities.

Tests exercise fresh-password checks, cross-user isolation, exclusion of security material, ownership-transfer safeguards, actual relational deletion, invalidated sessions/device credentials, and preservation of another member's account/workspace.
