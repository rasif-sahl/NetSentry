# Subscriptions and platform operations

Phase 14 uses the user-selected **provider-neutral sandbox**. There is no external checkout, live charge, paid account, tax invoice, store purchase or live-provider adapter. TST amounts are synthetic test units, not offered prices. Catalog limits are technical sandbox policy values and require product approval before sale. Production rejects sandbox mode and disables billing mutations. `BILLING_ENFORCEMENT=false` is explicitly labeled pre-release evaluation; feature flags still apply. Enable enforcement only after planning the effect on existing workspaces.

## Entitlements and lifecycle

The edition catalog supports Free, Premium, Family and Business, monthly/annual intervals, one 14-day trial per workspace, active/cancelling/grace/expired states, limits and retention bounds. Premium targets Personal, Family targets Family, Business targets Business. Monthly/yearly sandbox periods use UTC calendar boundaries with month-end clamping. Exact expiry is evaluated on every entitlement read, independent of workers. A valid paid sandbox period is ignored outside sandbox mode. Past-due grace lasts seven days from the earlier of the period end and event time. Changing edition/interval uses a reviewed revision-bound request and explicit simulated confirmation; there is no live proration or refund calculation.

Owner-only billing includes usage counters, pending request recovery, test payment history, cancellation and resumption. Other members see nonfinancial entitlements. Confirmation requires the original requesting owner and an unexpired request. Confirmed requests replay without a second payment. New device/agent/member/network allocations serialize on workspace locks and reject capacity overflow. Existing rows are preserved on downgrade. New retention settings cannot exceed enforced limits; downgrade does not silently shorten previously selected retention or delete history. Existing data reads, personal export, withdrawal, offboarding and deletion remain available.

Billing never grants workspace roles, local computer consent, OS permissions or monitoring capability. Enabling a feature flag cannot override a missing paid entitlement when enforcement is enabled. A false global or workspace flag disables that feature. Family, Business, advanced application, network and remote developer operations enforce the applicable feature separately from existing authorization. Local desktop control keeps its existing local authorization model.

`POST /api/v1/billing/events` is a **NetSentry normalized sandbox protocol**, not a payment-provider webhook format. Authenticate the exact raw JSON bytes using lowercase HMAC-SHA256 over `timestamp + '.' + body`, independent `BILLING_EVENT_SECRET`, `x-billing-timestamp` Unix seconds and `x-billing-signature`, with five-minute tolerance. Events carry a globally unique ID and monotonically increasing per-workspace sequence. Conflicting IDs/sequences reject; exact replay is harmless; older sequence events are recorded without reversing current subscription state. Payment IDs are independently deduplicated and bound to workspace/amount/currency. Bodies/cards are not retained, only hashes and minimal state/history. A future live adapter must authenticate its provider, reconcile authoritative state and produce this ordering; arbitrary provider delivery order is insufficient.

Billing request history is bounded to 1,000 per workspace and requires operator review at capacity. Receipt/idempotency history has no automatic pruning in this release; do not remove it casually or reuse IDs. Account/workspace erasure cascades billing records. A production financial-record retention policy must be decided with the live integration.

## Separate operator authority

Ordinary account/workspace ownership grants no platform administration. An active verified account needs an explicit, expiring database `OperatorGrant`: SUPPORT, BILLING or ADMIN, with enumerated workspace IDs. The CLI command is `npm --prefix backend run operations:grant -- USER_UUID ROLE WORKSPACE_UUID[,WORKSPACE_UUID] GRANT_FOR_8_HOURS`. Review its usage before running; global-account and global-catalog rights additionally require explicit environment flags and ADMIN. No default administrator or production grant is seeded. Revoke grants directly through reviewed database operations or let them expire; CLI grants and operations write minimal audit records.

Operators see only scoped workspace health, active/stale agent counts, sanitized versions, failed jobs/deliveries and audit. SUPPORT cannot view subscription details. BILLING/ADMIN can inspect scoped subscriptions; there is no manual live paid-benefit override. Redacted support exports contain counts, scope and generation time, excluding credentials, application usage, project paths and notification bodies. Global user controls require ADMIN plus global-account permission, fresh password and cannot target the operator's own account. Suspension revokes sessions; reactivation never restores old tokens. Pending-deletion accounts cannot be reactivated by this control.

Feature/catalog changes require ADMIN, the relevant explicit scope, fresh password and a current revision. Advisory transaction locks prevent lost updates. Router/device/agent/category entries are compatibility metadata with evidence, not executable adapters, automatic app classification or hardware certification. Public capabilities remain grounded in the existing tested implementations.

Schedule `npm --prefix backend run operations:work` alongside the existing per-workspace workers. It removes at most 1,000 expired grants and 1,000 audit records older than 90 days per invocation; repeat after backlog. API startup installs no scheduler. Minimal operator actions involving an account actor appear in that actor's privacy export.

## Deployment and release boundary

Apply all sixteen migrations explicitly before starting the updated backend. `/api/v1/health` is liveness; `/api/v1/ready` verifies database access and exact migration parity. Readiness does not certify workers, email/push providers, routers or a production deployment. Container source uses nonroot users, private listener ports, read-only filesystems, explicit secrets and reviewed image digests; image build/runtime and ingress acceptance are separate checks.

Encrypted PostgreSQL backup/restore and offline Ed25519 package verification are operational tools, not an installed hosting platform or automatic updater. See [deployment runbook](../../infra/phase-14-runbook.md). No production schema, account, signing key, daemon, scheduler or provider is provisioned. Production billing, native store/distribution, device testing, signed/notarized installers, atomic replacement/recovery and supported hardware remain explicit launch gates.
